# Herdr binaries this machine has legitimately produced or verified.
#
# The install guard's real question is "did this binary come from somewhere I
# trust?", not "is this the one official release the script was written
# against". Pinning a single predecessor digest meant the guard fired on every
# upgrade after the first, because from then on the binary being replaced is the
# *previous reviewed build* — which is the most trustworthy predecessor there is.
#
# So provenance is recorded here instead. build.sh appends a digest whenever it
# produces or installs one; install.sh and build.sh accept any listed digest as a
# replaceable predecessor. Anything not listed is still refused, which is the
# property worth keeping: an unrecognized binary in ~/.local/bin is never
# silently overwritten.
#
# Lines are "<sha256>  <what it is>". Append only — deleting a line does not make
# a binary untrustworthy, it just makes a future upgrade stop and ask.
