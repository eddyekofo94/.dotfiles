# FFF locale-sensitive integrity diagnosis — 2026-07-30

## Trigger

The physical Herdr/Fish pane repeatedly failed FFF verification while separate
automation and PTY shells reported the exact tree as valid.

## Root cause

FFF verification hashes the ordered `shasum` output for every package file.
The package files and individual hashes were identical, but `sort -z` inherited
the caller's locale:

- C ordering produced the reviewed source/tree pins.
- The physical pane's UTF-8 ordering produced different aggregate hashes.

This was a deterministic environment bug, not package tampering or runtime
mutation.

## Fix and prevention

- Both source and full dependency-tree hash pipelines force `LC_ALL=C` for
  filename ordering.
- `pi/verify.sh` launches the isolated pilot under C and `en_US.UTF-8` and
  requires the same pinned result.
- The structural verification-isolation test requires the canonical sort and
  both-locale launch regression.
- Exact-pane launch, reload, exit, restart, and concurrent-verification checks
  pass.
- Fresh review reports Standards 0 findings and Fidelity 0 findings.

Physical interaction acceptance remains open.
